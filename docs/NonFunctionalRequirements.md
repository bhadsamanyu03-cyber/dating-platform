# Non-Functional Requirements

## Confirmed qualities

The platform must be secure, maintainable, testable, observable, configurable by environment, and deployable through repeatable automation. It must use the established modular-monolith architecture unless a documented architecture decision changes it.

## Requirements pending product-owner decisions

Availability objectives, latency budgets, regional coverage, supported devices, localization, privacy posture, data-retention periods, support commitments, and cost constraints have not been specified.

## Open Questions

- What uptime target applies to the public service?
- What countries or regions require data residency?
- Which mobile OS versions, devices, and network conditions are supported?
- What accessibility conformance target is required?
- What recovery-time and recovery-point objectives apply?
